# 修复摘要

## 修复的问题
修复 impala 4.5.2 镜像构建时因 `/usr/lib64/libssl.so.1.1` 已存在导致 `ln -s` 报 `File exists` 而构建失败的问题。

## 修改的文件
- `Bigdata/impala/4.5.2/24.03-lts-sp4/Dockerfile`: 将 OpenSSL 库符号链接命令 `ln -s` 改为 `ln -sf`（第 28、29 行），允许覆盖已存在的同名文件。

## 修复逻辑
分析报告指出根因是基础镜像由 `24.03-lts-sp2` 升级为 `24.03-lts-sp4` 后，系统自带的 `/usr/lib64/libssl.so.1.1` 已存在，而 Dockerfile 第 28 行使用无 `-f` 的 `ln -s`，遇到已存在文件即报错并以 exit code 1 终止，`&&` 链中断，后续 `libcrypto.so.1.1` 链接也未能执行。采用分析报告方向 1（置信度高），对两处链接命令均加 `-f` 强制覆盖，确保仍指向自编译的 OpenSSL 1.1.1g，同时不破坏镜像内原有依赖。

仅修改失败步骤直接相关的两行，未改动 README、patch、meta.yml 等无关文件；`libffi` 符号链接（第 18 行）在本轮构建中已成功通过，不属于本次失败根因，遵循最小化原则未作改动。

## 潜在风险
无。`-f` 仅使已存在文件被覆盖，符号链接目标仍为自编译的 `/usr/local/openssl/lib` 下库文件，不改变链接语义。
